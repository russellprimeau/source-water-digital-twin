# Postprocess

Post-processing scripts and retained datasets for the Delft3D FM modelling of the
Brusdalsvatnet reservoir, together with the path-planning method for data collection by
uncrewed surface vessels.

This repository accompanies the manuscript *A Digital Twin Prototype for Protecting
Surface Source Waters*. It holds the analysis code and the derived datasets the figures
are drawn from. It does not hold the simulations themselves: re-running the underlying
models requires a separately obtained, appropriately licensed Delft3D installation and
the original inputs, and the hydrological forcing depends on third-party records that
cannot be redistributed. Reproducing a plot from the retained artifacts is therefore not
the same as reproducing the simulation behind it.

## Environment

```
.venv/Scripts/python -m pip install -r requirements.txt
```

All commands below are run from the repository root.

`data/Calibration.csv` is the retained record of the calibration campaign: one row per
configuration, with the mesh, vertical discretization, water clarity, filtering options,
eddy coefficients, Courant limit and timestep used, and the resulting error statistics.
It is the source both for Figure 6 and for the table of calibration ranges in Appendix B.
The campaign was carried out by iterative manual adjustment, so the file records the
configurations that were kept rather than a reproducible search path.

Appendix F's stability figures are produced by `src/PathPlanning/c.StabilityAnalysis.py`,
which writes both the summary datasets under `data/validation/` and the LaTeX fragment
`docs/manuscript/sampling_stability_results.tex` that the appendix includes, so the
reported numbers cannot drift from the analysis that produced them.

Figures marked as produced outside this repository come from the model post-processing
tools that read the solver's native output files. Those output files are large and are
not distributed; the derived series plotted in Figure 14 are retained instead.

## Path planning

Run in order. Each step writes the input the next one reads.

```
.venv/Scripts/python src/PathPlanning/a.PointSelection.py
.venv/Scripts/python src/PathPlanning/b.PathOptimization2.py
.venv/Scripts/python src/PathPlanning/PathPlotter2.py
.venv/Scripts/python src/PathPlanning/c.StabilityAnalysis.py
```

`a.PointSelection.py` normalizes the model-spread scores, selects the highest-scoring
cells and clusters them by separation distance. `b.PathOptimization2.py` searches for the
highest-weight route within the distance budget. `PathPlotter2.py` draws the result over a
basemap. `c.StabilityAnalysis.py` repeats the whole chain under leave-one-out and
bootstrap resampling of the retained cells.

`PathPlotter.py` offers alternative interactive renderings and is not needed for the
manuscript figures.

## Water quality post-processing

```
.venv/Scripts/python src/D3D/NewWAQPlots.py
.venv/Scripts/python src/D3D/WAQHisPostProcess.py
```

Both read the exported concentration series under `data/Nitrogen/` and raise on any value
that fails to parse, rather than silently treating it as missing. `NewWAQPlots.py`
produces Figure 8. `WAQHisPostProcess.py` produces the per-substance extrema and
cumulative-load summaries under `data/Nitrogen/SingleBlast/Eutroph/Analysis/`, which
support the text rather than a numbered figure; it opens plot windows by default, so set
`show_plots` to `False` in its configuration to run it unattended.

## Model configuration

`data/d3d/` holds the configuration of the thermal simulation reported in the manuscript:
the mesh, the `.mdu` and `.ext` control files, the boundary and meteorological forcing
series, the initial-condition fields and the DIMR configuration. It is provided so the
configuration can be inspected and the simulation repeated with an independently obtained
solver. It is not the configuration of every historical experiment described in the paper.

## Superseded

`src/superseded/` holds an earlier path optimizer, retained for reference only. It writes
to its own output filename and does not participate in the workflow above.
